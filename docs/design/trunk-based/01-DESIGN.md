# Trunk-based flow for Xavier

Status: proposed; ADR-035 acceptance decides policy direction before Phase 1, while branch-rule activation requires separate Phase 3 rollout gates and owner authorization. This design changes integration policy, not the release process. `main` is the trunk; working branches should last hours, with a 24-hour review trigger rather than an unenforceable four-hour expiry. One code feature (or bounded part) per PR, with its feature ID, remains the unit of change (`AGENTS.md:51-55`, `AGENTS.md:80-84`).

## 1. Two CI lanes

Keep the current CI observable during transition. The present workflow runs on PRs and `main` pushes (`.github/workflows/ci.yml:3-8`), but its full Rust test median is 9.7 minutes and Clippy median 3.2 minutes (`facts/FACTS.md:4-5`, Evidence (reproducible, captured 2026-09-27), lines 21-22). The new always-present `fast-gate` result is the only general required status check after it proves reliable. Its result must be **failure** when path classification is unknown, a job fails, or the workflow is cancelled; never treat a skipped check as success.

| Fast-gate job | Trigger and command shape | Target budget (including runner queue) |
| --- | --- | --- |
| `classify` | Always run; compare PR base/head; record paths, actor, risk class, reverse dependencies and classification in job summary. Reject unknown paths, >4 files or >400 changed lines from agent Ship, mixed high-risk paths, and a label that understates risk. | 20 s |
| `policy-security` | Every PR: staged/diff strategy and forbidden-file checks, path safety, version sync, `scripts/verify-pipeline.sh --check-only`, and full `scripts/check-secrets.sh` on the PR checkout. Require gitleaks or fail rather than use its weaker fallback in CI. | 45 s |
| `rust-scoped` | Only Rust-impacted PRs: `cargo fmt --all -- --check`; `cargo check` on impacted packages and reverse dependents with `ci-safe`; package-scoped Clippy and unit tests selected by the impact map. Run `-D warnings`. No blind test-name grep or zero-test success. | 150 s warm-cache goal |
| `ui-scoped` | `panel-ui/**` and shared UI contract changes: TypeScript check/unit tests/build as relevant; preserve the bundle token-canary before merge for UI changes. Browser smoke remains async on every `main` push. | 150 s goal |
| `fast-gate` | Always-run final job with `if: always()`, depends on all above; fail if any required selected job failed, was cancelled, or did not report; succeed for docs-only changes only after policy/security passes. Stable check name for ruleset. | < 180 s p90 for eligible PRs |

All budgets are targets, not current measurements. Jobs run in parallel. The 180-second goal applies to eligible PRs; publish separate results for Ask, cold cache and conservative fallbacks. If `cargo check` or a test target cannot reliably finish, keep it required and accept a slower gate until code/test isolation or caching is proven. Do not move a failing safeguard async solely to hit the number. The existing `rust-clippy` job checks only package `xavier` (`.github/workflows/ci.yml:69-92`); the new impact map must cover the workspace dependencies too (`Cargo.toml:40-59`, `Cargo.toml:247-250`).

**Rust impact map, first version.** Generate package ownership from workspace manifests, then maintain a small explicit reverse-dependency map. `src/**` selects `xavier`; `crates/xavier-core-logic/**` selects that crate and `xavier`; `code-graph/**` selects changed parser/crate, `code-graph` and `xavier`; `crates/xavier-wasm/**` selects WASM plus its dependents. `tests/**` selects the owning test target and root crate. `Cargo.lock`, root/workspace manifests, `.cargo/**`, `build.rs`, `vendor/**`, CI/impact scripts, or an unknown file select all affected workspace packages and trigger a conservative full pre-merge path if the selected checks exceed the fast budget. Root library tests are serial by necessity (`.github/workflows/ci.yml:144-154`); initially run them before merge for source changes unless a module-to-test mapping has shown, against historical PR failures and shadow runs, that selected tests catch the same failures. A zero selected-test result fails. Do not infer safety from an unrelated green package. `panel-ui/src-tauri` is excluded from the root workspace (`Cargo.toml:40-47`); classify it separately and require an explicit build/test recipe before it can use Ship or Show.

**Async post-merge lane.** On every new `main` SHA, run full root library tests, workspace package tests where CI-safe, the observability integration target, browser smoke for every change, full Clippy/MSRV, full ledger `scripts/verify-pipeline.sh`, coverage and available audits; schedule any service-dependent E2E against a controlled environment. Current root tests and the single observability target are documented in `.github/workflows/ci.yml:116-182`; current browser smoke deliberately runs on all changes (`.github/workflows/ci.yml:198-254`). Keep coverage report-only until the tarpaulin parser issue is fixed (`.github/workflows/rust-coverage.yml:20-53`). A test requiring unavailable services is reported as **not run**, never green. Scope expensive perf to scheduled/release runs, with a baseline and regression threshold before using it as a failure signal. Secrets and token-canary checks stay pre-merge, not only async (`.github/workflows/ci.yml:184-196`, `.github/workflows/ci.yml:230-245`).

**Failure response.** A failed `main` run opens or updates one `tbd-incident` issue keyed by SHA, linking failed jobs, change PR, response agent and run logs, then notifies the owner through the operator app (Atlas) and GitHub issue. The current Jules notifier exits for `main` failures (`.github/workflows/jules-ci-feedback.yml:29-40`); extend or replace that path. The independent rollback guardian in [07-ROLLBACK-GUARDIAN](07-ROLLBACK-GUARDIAN.md) decides a reversible rollback against a verified last known-good target. For a confidently attributable code regression, it may open an **auto-revert PR** with the inverse diff; deterministic gates and the agent panel approve the PR before merge. Never force push or mechanically revert schema/data migrations or security incidents. Close the incident only after the restored target is healthy. A Git revert does not undo a local binary deployment or published tag (`facts/FACTS.md:9`; `.github/workflows/release.yml:3-8`).

## 2. Ship / Show / Ask as review timing

GitHub labels: exactly one of `flow:ship`, `flow:show`, `flow:ask`; automation computes the **minimum** class from paths and diff. An agent may request a stricter class but cannot downgrade it. Labels do not bypass the fast gate. All agent changes use PRs. Identify the human owner from an explicit GitHub login allowlist; classify every other account, bot and token as an agent. Never trust a self-declared PR checkbox or author label. The agent panel can request a stricter classification with a recorded rationale; protected path rules still win.

| Class | File/path rule and examples | Human | Autonomous agent |
| --- | --- | --- | --- |
| **Ship** | Comments or spelling in non-publishing paths with no behavior, contract or config change. Max 4 files/400 changed lines; no generated artifacts. | Short PR, auto-merge after gate; owner emergency bypass only by documented exception. | Allowed via PR and auto-merge after gate; no direct push. |
| **Show** | Bounded internal refactor in `src/**`, `crates/**`, or `code-graph/**`; behavior preserved with tests; no public API, migration, auth, crypto, permissions, config default, feature activation or CI/ruleset change. Explicit impacted tests and feature ID. | PR, gate then auto-merge; agent panel records post-merge review. | Allowed via PR only after gate and independent diff review by orchestrator/another agent; agent panel records post-merge review. |
| **Ask** | `docs/**` or `panel-ui/**` changes that trigger public Pages deployment (`.github/workflows/deploy-docs.yml:3-12`); `docs/design/**`, `docs/adr/**`, `docs/SRS/**`, `docs/features/**`, `.gitcore/**`, `.github/**`, `.husky/**`, `scripts/check-secrets.sh`, `scripts/verify-pipeline.sh`, `Cargo.toml`/`Cargo.lock`, `.env.example`, schema/migrations, public HTTP/CLI/MCP contracts, auth/crypto/security, release/deploy and any ambiguous or mixed-risk change. | Independent agent-panel approval before merge. | May author a PR; independent agent-panel approval required before merge. ADR acceptance uses the same panel; branch-rule activation remains in the owner's final acceptance. |

Default unknown paths to Ask. A diff touching a higher-risk path takes the higher class. Every rollback revert PR requires guardian evidence and pre-merge panel review regardless of its computed Ship/Show/Ask class; never auto-merge it. Every change that auto-publishes outward requires pre-merge panel review. Public docs publication is reversible and listed in the next Product Acceptance Package; if the owner has not pre-authorized that publication class, the merge waits. Treat new code behind a flag as Show only when it cannot execute under current defaults, has no public contract/schema/security change, and the flag itself has a documented owner and removal date; otherwise Ask. The proposed blanket rule “flagged code = Ship” is unsafe here. A code PR references one feature ID per `AGENTS.md:80-84`; docs-only maintenance uses an issue link instead. Ask review target is <1 business hour from `ready_for_review` to the panel's recorded verdict; if missed, wait rather than auto-merge. Four hours is a branch-age prompt, not a reason to skip review.

## 3. Branch rules and merge mechanics

Agents prepare a single active `main` ruleset: no deletion/force push; require PR; require the stable `fast-gate` status on the current SHA; require conversation resolution; allow auto-merge and squash. Branch-rule activation is an outward action presented for owner authorization in final product acceptance. A required `policy` check verifies that `flow:ask` has deterministic gate results, two independent model approvals (neither the author) and a stored report for the current head SHA. It also requires guardian evidence and pre-merge panel approval for every rollback revert PR. For every outward-publishing PR it requires pre-merge panel approval and recorded owner pre-authorization of the publication class. For eligible non-publishing, non-rollback Ship/Show, the policy check confirms the class and permits auto-merge. Fail closed if any required panel evidence is missing, stale or disputed. Re-evaluate on PR open/update, label changes and review submissions; run with a read-only token for untrusted PR code. Turn on merge queue only if concurrent PRs produce stale results; otherwise require branches up to date before merge. Trial the ruleset on a non-default branch, then enable after shadow gate reliability and recovery drills.

Only the human owner holds any direct-`main` bypass, for a documented emergency with a linked incident and immediate follow-up PR/check. Agents and bot tokens have no bypass or direct-push permission. This is a deliberate departure from direct Ship pushes: under the current rules, such pushes have no required check (`facts/FACTS.md:2`, Evidence (reproducible, captured 2026-09-27), lines 11-20). Do not enable direct push as Phase 3 simply because the calendar reaches week three.

## 4. Hooks and code migration conventions

Keep `.husky/pre-commit` and `.husky/pre-push` (`AGENTS.md:90`; `.husky/pre-push:1-5`). Pre-commit should enumerate `git diff --cached --name-only -z --diff-filter=ACMR`, inspect staged **index blobs** (including new files), reject runtime DBs, paths and staged strategy/secret leaks, and run `rustfmt` only on staged `.rs` files without modifying unstaged content. Move full `cargo fmt --all`, Clippy and UI build to CI/on-demand pre-push, since the current hook does whole-project work (`.husky/pre-commit:15-55`). Do not let absence of Node silently disable the pre-push guard; fail with an actionable message or provide a shell equivalent (`.husky/pre-push:3-5`). The CI scan must fail if gitleaks is unavailable; the local fallback remains a convenience, not security evidence (`scripts/check-secrets.sh:15-33`). Never auto-stage changes in a hook.

For a long migration, first add a trait/interface at the narrow call boundary, ship an adapter that preserves old behavior, add the new implementation behind a Cargo feature or documented environment toggle, redirect one caller at a time, then remove the old path and toggle after a green post-merge window. Cargo features already separate optional capabilities and `ci-safe` (`Cargo.toml:61-86`); configuration is environment based and new keys must be added to `.env.example` (`AGENTS.md:63-69`). Keep a new runtime flag off by default, name its owner and removal condition in the feature spec, test off/on paths, and use no flag service. A feature flag is not a substitute for review of API/schema/security changes. Release tags and local binary installation remain separate from merge (`.github/workflows/release.yml:3-8`; `facts/FACTS.md:9`).

## 5. Four-phase rollout with exit criteria

| Phase | Work | Exit criterion |
| --- | --- | --- |
| **1. Baseline and hygiene** | After panel acceptance of ADR-035 based on simulation, deterministic gates, two independent approvals and report, update `AGENTS.md` PR verification wording; record CI/DORA baseline, inventory failed tests, fix actual flakes only if observed, introduce staged Husky changes and a shadow fast gate; restore explicit full ledger execution after merge while PR gets structural verification. | Two weeks of shadow runs with no unclassified PR, no missing secret/ledger results, all failures linked to checks, and a demonstrated `main` incident/revert drill. Existing checks remain visible. |
| **2. Classification** | Add labels, changed-path policy and PR template; trial Ship/Show/Ask on PRs without changing protections. Compare impact-selected checks to full checks. | 100% of sampled PRs have the correct or stricter label, one feature ID/issue link, no missed full-suite failure in the shadow sample; p50/p90 gate times published by path class. |
| **3. Protected integration** | Agents prepare ruleset, required always-run fast gate and auto-merge for eligible non-publishing, non-rollback Ship/Show; owner authorizes branch-rule activation in final acceptance. Ask panel approval remains mandatory. Agents continue to use PRs. | Verify a rejected direct agent push, rejected stale/unclassified PR, blocked Ask without current panel evidence, blocked rollback revert without guardian evidence or pre-merge panel approval, blocked Pages-triggering PR without pre-merge panel approval and owner class pre-authorization, successful eligible Ship/Show auto-merge, and automatic incident creation on a simulated `main` failure. If the selected gate misses a full-suite failure, revert to the prior required-check set. |
| **4. Operate and adjust** | Review weekly GitHub metrics; improve cache/test seams, triage post-merge failures, tune only evidenced path mappings. | Four weeks of measured lead time, MTTR, change-failure rate and fast-gate p50/p90; documented response for every red `main` run; retain or roll back the policy based on those results. |

The Skill Controller proposal on `design/skill-controller` can teach agents the labels, scope limits and evidence format. It is advisory: GitHub path classification, status checks and branch rules remain the enforcement boundary. Keep its rollout independent so failure or delay there does not block this policy.
