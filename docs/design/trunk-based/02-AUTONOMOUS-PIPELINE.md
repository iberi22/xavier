# Autonomous delivery pipeline

Status: proposed implementation contract, 2026-09-27. Read with [01-DESIGN](01-DESIGN.md), [ADR-035](../../adr/ADR-035-trunk-based-ship-show-ask.md), and [03-DONE-PROTOCOL](03-DONE-PROTOCOL.md). The owner has not accepted the proposed change to Ask/ADR approval. Existing `AGENTS.md` and ADR-035 gates apply until that decision is recorded.

## Operating boundary

One orchestrator owns an Atlas session and an issue/PR chain for each product increment. It reads Xavier memory, delegates bounded tasks to Codex, agy, OpenCode or Jules, and independently gathers evidence. Atlas stores the DAG, DoD and evidence pointers; GitHub stores source, PRs, Actions results and incident history. CI artifacts hold generated evidence and reports. No new service or repo-local runtime database is needed. A task is at most four changed files and 400 changed lines; split larger work into dependent tasks. One code PR references one feature ID. All agent integration uses a PR, never a direct `main` push.

The coordinator computes `flow:ship`, `flow:show` or `flow:ask` from the actual diff under 01-DESIGN. The label controls review timing, never verification strength. Unknown and mixed paths become Ask. The current Ask rule still requires owner approval. The recommended agent-panel alternative is below and needs owner confirmation before it replaces that rule.

## Stages and gates

Every stage writes an evidence record tied to `session_id`, task/feature ID, repository, base SHA, head SHA, timestamp, producing backend and artifact/URL. The next stage reads the previous stage's accepted record, not an agent's prose claim. A missing, stale or mismatched record blocks advancement.

| Stage; owner/backend | Inputs → outputs | Machine-checkable exit and stored evidence |
| --- | --- | --- |
| 1. Idea/intake; orchestrator + Atlas | Owner goal or verified incident → single problem statement, target outcome, feature ID or maintenance issue, non-goals | Atlas session/issue exists; unique ID, acceptance examples and measurable outcome are present; Xavier search query/result reference and source links recorded. Unverified external numbers are marked assumptions, not facts. |
| 2. Research; research agent, independent fact checker | Intake + repo/primary sources → short fact table and risks | Each material claim has a path/line, command output or dated source URL; checker reopens cited source and records `confirmed`, `assumption` or `rejected`; no rejected claim enters design. Store source URLs, retrieval date and review report in Atlas evidence. |
| 3. Design/ADR; design agent + independent review panel | Confirmed facts + existing ADRs/SRS → design, migration/rollback plan, ADR for non-obvious change | Required ADR fields and simulation/report (when ADR requires one) exist; references resolve; deterministic policy/secret/path checks pass; two independent model reviews return explicit `APPROVE` after issues are resolved. Record model IDs, verdicts, report links and ADR SHA. Current owner acceptance still gates ADR-035/Ask. |
| 4. Task DAG; orchestrator + Atlas | Accepted design → tasks, dependencies, DoD and allowed path lists | DAG has no cycle or orphan; each task has ≤4 paths and a fixed 400-line change cap, explicit test commands, rollback owner and backend; dependency IDs resolve. The actual line count is enforced on the diff. Store the serialized DAG, scope manifest hash and Atlas IDs. |
| 5. Implementation; selected executor backend | Ready Atlas task + isolated worktree + allowlist → diff and test changes | Executor output is treated as a proposal. Coordinator checks Git worktree identity, realpath, base/head diff, changed paths, size, symlinks and forbidden files; changed paths must be a subset of task allowlist. Inspect *all* worktrees created for the task, including the expected worktree, and quarantine unexpected writes. Store diff SHA, backend, command transcript and scope report. |
| 6. Verification; CI runner + independent reviewer | Exact candidate SHA + declared commands → check results and review | Deterministic checks run first: scope/path-leak/secret guards, `verify-pipeline.sh --check-only`, impact-selected checks and all declared task commands. Full ledger execution runs before any feature is marked stable. Every required command has observed exit 0 and nonzero test count where applicable. Then independent cross-model critique returns explicit approval. Store command, exit, duration, log artifact, test count, CI URL and reviewer report keyed to SHA. |
| 7. Integration; orchestrator + GitHub PR/CI | Verified candidate + feature ID → gated PR, merge SHA, main run | One feature per code PR; computed class matches label; required current-head checks, conversations and current Ask approval pass. Merge only through configured ruleset/queue. Re-check scope and evidence against final PR SHA. On `main`, full CI and `scripts/verify-pipeline.sh` must pass before increment is offered as accepted. Store PR, checks, merge SHA and main run URLs. |
| 8. Release/handoff; release agent + owner | Green main SHA + DONE bundle → candidate release and Product Acceptance Package | Candidate version, trial steps, artifact checksums, risks and rollback path are reproducible. Docs Pages result is linked if triggered. Tag/public release, local install, ruleset or secret changes, spending and other outward or irreversible actions wait for explicit owner authorization. Store release/deploy run URLs and accepted artifact SHA only after executed. |

`scripts/verify-pipeline.sh --check-only` validates structure only. Full mode can silently skip tests when `cargo` is absent, so the wrapper must first assert `command -v cargo`, run the full script, and inspect its log for actual declared-test execution. A zero selected-test count is a failure. No ledger status is hand-promoted; only the green pipeline may promote it.

## Gate order and review adapter

1. Freeze candidate SHA and manifest. Run local deterministic policy checks; fail on an unavailable scanner, unknown path or missing command. Run the corresponding CI jobs on the same SHA. A CI `skipped`, `cancelled`, missing or stale check is not a pass.
2. Run `atlas --json verify <task-id>` for its DoD and evidence rule layer. Its current reviewer is advisory: `passed: true` does **not** mean the model approved, and an unset `ATLAS_REVIEW_CMD` uses a deferring stub. The delivery gate separately requires a real reviewer result.
3. Set `ATLAS_REVIEW_CMD` to a checked-in adapter which consumes Atlas's JSON on stdin, calls `$HOME/.hermes/scripts/co-agent-review.sh verify <worktree> <claim-file>` and emits exactly `{"verdict":"approve"|"reject","notes":"..."}`. Bind the claim file to the candidate SHA and task evidence. The adapter must convert `PARTIAL`, malformed output, timeout or nonzero exit to `reject`, and preserve the full report. `ATLAS_REVIEW_TIMEOUT_MS` must exceed the helper timeout. For code diffs also run `co-agent-review.sh critique <worktree> <base>..<head>` and parse only `VERDICT: APPROVE` with zero blocking defects. Never infer approval from the helper's exit code alone (`PARTIAL` currently exits 0).
4. The coordinator's DONE checker parses Atlas JSON and the separate saved model report; it fails unless `passed=true`, `reviewer=cmd:approve`, the reviewer identity differs from the implementing backend, and both report SHAs equal the candidate SHA. Review is last, after factual execution evidence. Two critique/fix rounds maximum per candidate; any edit invalidates prior CI/review and starts a new SHA cycle.

## Failure containment and bounded retries

| Observed failure in PIPELINE-FACTS | Automatic detection or prevention |
| --- | --- |
| Codex waits on stdin | Launch CLI with stdin closed (`</dev/null`) unless a declared interactive protocol is needed; enforce wall timeout and capture process tree/exit. |
| Model returns zero bytes or hangs | Capture stdout/stderr byte count, heartbeat and last progress time; zero-byte completion is failure. At 90 seconds without output/heartbeat, probe once; terminate after another 90 seconds without progress. A long quiet build uses a wrapper heartbeat plus its own wall timeout, so silence alone does not kill healthy compilation. |
| agy edits a second checkout | Create one task worktree, enumerate task-created/known checkouts before and after, compare `git status --porcelain -z` and hashes; reject/quarantine any unexpected write. CI repeats changed-path guard against `base...head`, which also catches out-of-scope committed files. |
| Personal absolute path in public docs | Scan added text lines and all new text blobs for `/home/<user>/`, `/Users/<user>/`, `C:\Users\<user>\`, `/tmp/claude-*` and configured private roots; allow `$HOME` and relative paths. Scan commit contents in CI, not just a local hook. Fail closed on binary/unknown files requiring inspection. |
| Invented external numbers | Require a source URL/date or reproducible query for each figure; independent fact checker verifies it; absent evidence becomes an explicit assumption and cannot support an ADR score or acceptance claim. |
| Claimed checks never ran | Compare every declared command against independent execution records for the candidate SHA: exact argv, runner, start/end, exit, log URL and test count. Coordinator/CI re-runs commands; prose, Atlas free-form evidence and screenshots alone never satisfy a check. |

An executor gets at most **two attempts total** per task. Retry once on a different available backend after a transient failure or hang; keep the same scope and invalidate the failed attempt's evidence. Deterministic test, policy or reviewer rejection is fixed by a new task/commit, not retried unchanged. If both attempts fail, Atlas marks the task `FAILED`/`BLOCKED`, opens or updates a GitHub issue with logs and failed SHA, and leaves descendants blocked; an agent may split/re-plan the DAG, with owner alerted only when an irreversible decision or genuine product tradeoff is required. No infinite relaunch loop. Deduplicate incidents by task ID or main SHA.

Suggested wall limits: executor 30 minutes; no-output probe at 90 seconds plus 90-second grace; reviewer 15 minutes; PR CI 25 minutes (recent p90 is 11.1 minutes); full ledger 2 hours with per-test limits; release build 60 minutes. Treat these as initial budgets, record observed durations and adjust only from measurements. Timeout, signal, missing heartbeat or no bytes after a supposedly successful executor run is a failed attempt. Poll GitHub/Atlas with a finite deadline and record the final state; do not leave a `running` task indefinitely. Agent retries cannot waive a red deterministic gate.

## Owner decision recommended

Recommend that the owner **confirm** a policy amendment: an ADR and other reversible Ask design decisions may be accepted by an agent review panel after deterministic checks, required simulation, two independent model approvals and an auditable report. The human would see the accepted decision in the final Product Acceptance Package. Until the owner records this amendment and updates ADR-035/`AGENTS.md` and the required GitHub policy check, Ask still needs owner approval and ADR-035 remains proposed. The minimal continuing human decisions should be final product acceptance and explicit authorization for outward or hard-to-reverse actions: branch protection/rulesets, credentials, paid capacity, public tags/releases, production/local deployment or data migration. A failed final product review returns a concrete issue to Atlas; agents do the repair and resubmit a fresh package.
