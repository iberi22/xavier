# [Ola 2 · 01] Añadir `local` y `ollama` al array de providers del ProxyUseCase

> Parte de la iniciativa **Xavier 100% Local (LLM + embeddings vía Ollama) — Ola 2**.
> Issue hermano de los issues 02 a 14 de la misma ola. **No cablear el fallback ante fallo** en este issue — eso es el issue 02.

## 🎯 Contexto

El chat del panel (`/v1/chat` y `panel_process_chat`) termina llamando a
`ProxyUseCase::execute_secured` (`src/app/proxy_use_case.rs:203`), que en la línea 235
resuelve el proveedor con un array **hardcodeado**:

```rust
let providers = [
    "opencode-go",
    "deepseek",
    "groq",
    "openrouter",
    "google",
    "openai",
    "anthropic",
];
```

Este array **no incluye** `"local"` ni `"ollama"`. Como consecuencia, aunque el usuario tenga
Ollama corriendo y `XAVIER_MODEL_PROVIDER=local` configurado, el chat del panel nunca
considera el proveedor local como candidato. Además, si todos los proveedores cloud están
agotados, `execute_secured` devuelve `ProxyError::RateLimited` (línea 263) y el usuario ve
"No pude contactar al modelo de IA".

La infraestructura de verificación ya existe: `ModelProviderConfig::is_reachable()`
(`src/agents/provider/config.rs:469`, PR #547) y `ProviderRouter::is_ollama_reachable()`
(`src/agents/provider/router.rs:131`).

## 📋 Problema

1. El proveedor local (Ollama) es invisible para el `ProxyUseCase`.
2. No hay forma de que el chat responda usando el LLM local aunque esté sano.

## ✅ Criterio de aceptación

- [ ] El array `providers` en `src/app/proxy_use_case.rs:235` **incluye** `"local"` (y opcionalmente `"ollama"` como alias) además de los cloud existentes.
- [ ] Antes de aceptar `"local"` como `selected_provider`, se valida que está reachable usando `ModelProviderConfig::for_provider("local").is_reachable().await == ProviderReachability::ConfiguredAndReachable` (o equivalente). Si no es reachable, se salta al siguiente (igual que cuando un cloud está rate-limited).
- [ ] `"local"` se coloca **al final** del array para preservar el comportamiento cloud-first actual (el issue 04 define el orden real de la fallback chain; aquí basta con que local sea candidato).
- [ ] `cargo check -p xavier` pasa limpio.
- [ ] Existe un test unitario en `src/app/proxy_use_case.rs` (`#[cfg(test)] mod tests`) que verifique que `"local"` aparece en el array y que cuando todos los cloud están rate-limited y local es reachable, `selected_provider == Some("local")`. Se puede mockear el `RateLimitManager` marcando todos los cloud como rate-limited; para el reachability se puede mockear red o usar `#[cfg(test)]` con feature flag — si es muy acoplado, basta con un test documentado que asuma Ollama en `localhost:11434`.
- [ ] **NO** se implementa lógica de fallback ante fallo del proveedor elegido (eso es el issue 02). Este issue solo amplía el set de candidatos y lo filtra por reachability.
