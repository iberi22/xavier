# [Ola 2 · 09] Tests de integración del chat con fallback chain y memory-fallback

> Parte de la iniciativa **Xavier 100% Local (LLM + embeddings vía Ollama) — Ola 2**.
> Issue de **tests únicamente** (no cambia behavior de producción). Crea un solo archivo nuevo.

## 🎯 Contexto

Los issues 01, 02 y 03 añaden tres comportamientos clave al chat:

1. `local` es candidato de `execute_secured` (issue 01).
2. Si el provider elegido falla, salta al siguiente de la fallback chain con 1 reintento (issue 02).
3. Si todos fallan, responde desde memoria con `provider: "memory-fallback"` (issue 03).

Ninguno de los tres tiene hoy un test de integración **extremo a extremo** que dispare el flujo
real con HTTP mockeado. Los tests unitarios de cada issue cubren piezas, pero el contrato entre
`ProxyUseCase` ↔ `ProviderRouter` ↔ `MemoryQueryPort` solo queda validado con un test de
integración.

`mockito` ya es dependencia del workspace (ver `Cargo.toml` y `tests/proxy_integration.rs`).
`tests/proxy_integration.rs:46` ya llama `execute_secured` y es un buen patrón de referencia.

## 📋 Problema

Una regresión en el cableado del router (issue 02) o en el memory-fallback (issue 03) puede no
romper tests unitarios y llegar a producción. Falta un guardrail de integración.

## ✅ Criterio de aceptación

- [ ] Usar `mockito` para levantar dos mocks HTTP: `mock_provider_a` (devuelve 500) y `mock_provider_b` (devuelve un chat completion válido openai-compatible). Un `MemoryQueryPort` mock (en el propio test, struct impl `MemoryQueryPort`) que devuelve 2 docs.
- [ ] **Test 1 — fallback entre providers:** configurar `ProviderRouter` con `set_fallback_chain([A, B])`, construir `ProxyUseCase` con `with_provider_router(...)`, forzar que A falle (mock 500) y verificar que `execute_secured` reintenta con B y devuelve la respuesta de B (status 200, content del mock B). Verifica el issue 02.
- [ ] **Test 2 — memory-fallback cuando todos fallan:** configurar ambos mocks para devolver 500/error, verificar que el handler `headless_chat` (o una extracción de su lógica) devuelve 200 con `provider: "memory-fallback"` y content no vacío derivado de los docs del memory mock. Verifica el issue 03.
- [ ] **Test 3 — local como candidato:** construir un `ModelProviderConfig` con `base_url` apuntando a un mock que simule Ollama, verificar que `execute_secured` con todos los cloud rate-limited selecciona local y lo golpea. Verifica el issue 01.
