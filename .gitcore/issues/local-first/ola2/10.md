# [Ola 2 · 10] Endpoints `/v1/providers` y `/provider/status` devuelven datos REALES (incluido `local` y la fallback chain)

> Parte de la iniciativa **Xavier 100% Local (LLM + embeddings vía Ollama) — Ola 2**.
> Consolidación/verificación del trabajo iniciado en la Ola 1 (PR #525).

## 🎯 Contexto

Tras la Ola 1, `headless_providers` (`src/cli/handlers/headless_api.rs:150`) y
`headless_provider_status` (línea 198) ya devuelven datos, pero hay dos huecos:

1. En `headless_providers` línea 180 hay un comentario explícito:
   ```rust
   // Reachability check: In this phase, we use configuration as a proxy for reachability
   // to avoid blocking synchronous network I/O during the API call.
   // Future iterations (LOCAL1-01) may use a background health-check cache.
   let reachable = is_configured;
   ```
   Es decir, `reachable` **miente**: dice `true` siempre que el provider esté configurado, sin
   golpear la red. Para `local` esto es engañoso (puede estar configurado pero Ollama apagado).
2. `headless_provider_status` (línea 198) **no incluye** la lista de providers con su estado
   individual, solo `active`/`strategy`/`fallback_chain`. La UI necesita ambos en uno.

El issue 04 ya añade `mode` y `local_reachable` a `headless_provider_status`. Este issue 10 se
centra en que `headless_providers` deje de mentir sobre `reachable`.

## 📋 Problema

- `reachable` en `/v1/providers` es siempre igual a `configured` → la UI no puede distinguir
  "tengo OpenAI configurado pero la API está caída" de "todo OK".
- No hay un solo endpoint que devuelva providers individuales + cadena + modo activo.

## ✅ Criterio de aceptación

- [ ] Reemplazar `let reachable = is_configured;` (línea 180) por un check real. Como el comentario advierte sobre I/O bloqueante, usar **o bien** el cache de reachability (`REACHABILITY_CACHE` en `config.rs`, TTL 15s, ya implementado en `is_reachable` línea 484) vía `ModelProviderConfig::is_reachable().await`, **o bien** un campo precargado en el `CliState` por el background health-check del issue 06. Se prefiere `is_reachable().await` dado el TTL cache.
- [ ] El provider `local` debe aparecer en la lista cuando esté configurado (`XAVIER_MODEL_PROVIDER=local`) **o** en la fallback chain, con `reachable` reflejando si Ollama responde realmente.
- [ ] Unificar el shape: `headless_providers` y `headless_provider_status` deben ser **compatibles** (mismos nombres de campo: `active`, `mode`, `fallback_chain`, `providers[]`). Idealmente que `headless_provider_status` llame a la misma función interna que `headless_providers` para evitar drift.
- [ ] Mantener compatibilidad hacia atrás: campos existentes no se renombran ni eliminan.
- [ ] `cargo check` y `cargo test -p xavier --lib headless_api` pasan.
