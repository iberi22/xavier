# [Ola 2 · 06] Health-check de Ollama al arranque del servidor + log de resumen de modo local

> Parte de la iniciativa **Xavier 100% Local (LLM + embeddings vía Ollama) — Ola 2**.
> Mejora la traza de boot para que el usuario sepa de un vistazo si su setup local está sano.

## 🎯 Contexto

`src/cli/server.rs` **ya imprime** un resumen al final del boot (líneas 868–898):

```rust
let final_status = xavier::observability::health::HEALTH.run_checks().await;
println!("{} Xavier iniciado — modo: {}", mode_icon, mode_str);
println!("   LLM:        {}/{} @ {} [{}]", ...);
println!("   Embeddings: {}/{} @ {} [{}]", ...);
println!("   Vector DB:  {} ({})", ...);
```

Eso ya está cerca del objetivo. El issue pide:

1. **Asegurar** que ese bloque haga un `is_reachable()` real contra Ollama (no solo el derivado de `OperationalMode`), y registre una alerta en `SYSTEM_ALERTS` (`src/server/alerts.rs:34 push_alert`) si local debería estar up pero no responde.
2. **Promover** el `OperationalMode` al `SystemAlertStore` para que la UI (issue 07) y el endpoint `/provider/status` (issue 04) lo consuman de una sola fuente.
3. El formato deseado (objetivo, ya casi cumplido): `🟢 Xavier iniciado — modo: LOCAL | LLM: ollama/qwen3-coder [reachable] | Embeddings: ollama/embeddinggemma [reachable]`.

## 📋 Problema

- El boot log se apoya en `final_status.llm.reachable`, pero ese valor viene de `HEALTH.run_checks()`. Si ese check no golpea Ollama explícitamente, el `[reachable]` puede ser `unreachable` aunque Ollama esté fino.
- No hay persistencia del estado en `SYSTEM_ALERTS` que permita a la UI mostrar "degradado" de forma coherente tras el boot.

## ✅ Criterio de aceptación

- [ ] En el boot de `src/cli/server.rs` (justo antes del bloque 868–898 o dentro de él), llamar de forma explícita a `ProviderRouter::is_ollama_reachable().await` y a `ModelProviderConfig::for_provider("local").is_reachable().await`, y comparar con `final_status.llm.reachable`. Si hay discrepancia (p.ej. `is_ollama_reachable == true` pero `final_status.llm.reachable == false`), loguear `warn!` y pushear alerta `level="WARN"` componente `"llm"` al `SYSTEM_ALERTS`.
- [ ] Tras el boot log existente, añadir **una** línea compacta con el formato objetivo (aclarando provider + modelo + reachability en una sola línea), para terminales cortas:
  ```
  🟢 Xavier iniciado — modo: LOCAL | LLM: ollama/qwen3-coder [reachable] | Embeddings: ollama/embeddinggemma [reachable]
  ```
  (los valores de `qwen3-coder` / `embeddinggemma` deben venir de config, no hardcodeados).
- [ ] Si el modo es `LocalDegraded` o `Disabled`, el icono y mensaje cambian acorde (🟡/🔴) — ya está implementado, **verificar** que siga funcionando tras los cambios.
- [ ] `src/server/alerts.rs`: añadir un método `pub fn derive_operational_mode(llm_reachable: bool, embedding_reachable: bool, provider_setting: &str) -> OperationalMode` (o similar) que centralice la lógica hoy esparcida en `get_mode` (líneas 66–86), para que boot, UI y endpoints la compartan. Mantener `get_mode` funcionando (puede llamar a la nueva).
- [ ] `cargo check -p xavier` y `cargo test -p xavier --lib alerts` pasan.
- [ ] Test unitario en `alerts.rs` para `derive_operational_mode` cubriendo los 4 casos (`LocalHealthy`, `LocalDegraded`, `CloudFallback`, `Disabled`).
