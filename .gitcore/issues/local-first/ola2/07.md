# [Ola 2 · 07] UI Tauri: indicador visual de modo (local/cloud/degradado) y provider activo

> Parte de la iniciativa **Xavier 100% Local (LLM + embeddings vía Ollama) — Ola 2**.
> Trabajo frontend (React/TS en `panel-ui/`). No toca Rust.

## 🎯 Contexto

El panel ya tiene componentes de estado listos para extender:

- `panel-ui/src/components/TopStatusBar.tsx` (barra superior con métricas, hora, canales).
- `panel-ui/src/components/ProviderSelector.tsx` (selector de provider con badges `running`/`degraded`/`error`).
- `panel-ui/src/components/SystemAlertBanner.tsx` (banner de alertas del sistema).

El backend expone (tras los issues 04 y 06):

- `GET /provider/status` → `{ active, strategy, fallback_chain, mode, local_reachable }`
- `GET /v1/providers/status` (headless) → mismo shape.
- `GET /health` → `{ status, mode, llm, embeddings, vector_db }`.

`mode` puede ser `"local" | "cloud" | "degraded"`. El objetivo es que el usuario vea de un
vistazo si está operando 100% local, en cloud, o degradado, y qué provider está activo.

## 📋 Problema

Hoy la UI no refleja el modo de operación. El usuario no sabe si sus mensajes van a Ollama o a
un cloud pago hasta que mira la factura o los logs.

## ✅ Criterio de aceptación

- [ ] Crear `panel-ui/src/components/OperationModeBadge.tsx` (o ampliar `TopStatusBar.tsx`) que:
  - Hace polling cada ~10s a `/provider/status` (o `/health`).
  - Muestra un badge con icono y color:
    - `mode === "local"` → 🦙 **Local** (verde `#39ff14`).
    - `mode === "cloud"` → ☁️ **Cloud** (azul).
    - `mode === "degraded"` → ⚠️ **Degradado** (ámbar), con tooltip explicando que el LLM local no responde.
  - Muestra el provider activo (`active`) y, si `mode === local`, el modelo (p.ej. `qwen3-coder`).
- [ ] Integrar el badge en el header del chat (junto a `TopStatusBar` o como elemento del header del panel de chat en `App.tsx` o donde viva el layout). No romper el layout existente.
- [ ] Si el endpoint falla (red caída), mostrar el badge en gris con tooltip "Sin estado del servidor".
- [ ] `npm run -w panel-ui build` (o el script equivalente, verificar `panel-ui/package.json`) pasa sin errores TS.
- [ ] `npm run -w panel-ui lint` (si existe) sin warnings nuevos.
