# [Ola 2 · 05] Provider local real (no stub): validar el path openai-compatible hacia Ollama

> Parte de la iniciativa **Xavier 100% Local (LLM + embeddings vía Ollama) — Ola 2**.
> Convierte el archivo `local.rs` (un stub de 3 líneas) en módulo documentado + verifica
> que `ProviderMode::Local` produce una llamada HTTP correcta a Ollama.

## 🎯 Contexto

Hoy `src/agents/provider/local.rs` es literalmente:

```rust
/// This module currently serves as a placeholder for local-specific provider logic if needed.
/// Currently, local providers use the OpenAI or Anthropic compatible paths.
pub mod types {}
```

No hay nada que valide que, cuando `ProviderMode::Local` está activo, el cliente efectivamente
haga una llamada HTTP al formato correcto de Ollama (`http://localhost:11434/v1/chat/completions`,
openai-compatible, ver PR #540 / config.rs línea 123 que define `provider_mode: ProviderMode::Local`
con `base_url = DEFAULT_LOCAL_BASE_URL = "http://localhost:11434/v1"`).

El cliente vive en `src/agents/provider/client.rs:79 generate_text_with_cache`, que en línea 92
despacha a `generate_openai_compatible` (importada de `src/agents/provider/openai.rs:18`).
**Falta** una verificación + documentación de que para `ProviderMode::Local` ese dispatcher hace
lo correcto (base_url, sin API key, modelo `qwen3-coder`).

## 📋 Problema

1. `local.rs` es un stub; no hay un sitio claro donde documentar los contratos del modo local.
2. No hay test que garantice que `ProviderMode::Local` → request `POST localhost:11434/v1/chat/completions` con el body correcto.

## ✅ Criterio de aceptación

- [ ] `src/agents/provider/local.rs` deja de ser un stub vacío. Se convierte en un módulo que:
  - Documenta (doc-comment de módulo) el contrato: `ProviderMode::Local` usa el path openai-compatible contra `DEFAULT_LOCAL_BASE_URL`, sin auth header (Ollama no requiere key salvo `OLLAMA_API_KEY` opcional), modelo por defecto `qwen3-coder`.
  - Expone constantes/funciones auxiliares si conviene, p.ej. `pub const DEFAULT_LOCAL_MODEL: &str = "qwen3-coder";` y `pub fn build_local_request(...)` si ayuda a testear.
  - Mantiene `pub mod types {}` o lo elimina si está vacío y sin uso (cuidado con breaking — grep antes de borrar).
- [ ] Añadir un test de integración o unitario (en `local.rs` `#[cfg(test)]` o en `client.rs`) que usando `mockito` (o `wiremock`) levante un mock en `http://127.0.0.1:PORT/v1/chat/completions` y verifique que:
  - Un `ModelProviderConfig` con `provider_mode = Local`, `base_url = mock_url`, `model = "qwen3-coder"` produce una petición `POST` con JSON body `{"model":"qwen3-coder","messages":[...]}` y **sin** header `Authorization` (o con el valor opcional si `OLLAMA_API_KEY` está seteado).
  - La respuesta del mock (un JSON openai-compatible) se parsea a `LlmResponse` correctamente.
- [ ] Confirmar que `client.rs:92` (`generate_openai_compatible`) efectivamente se llama cuando `provider_mode == Local`. Si no es el caso (si el dispatcher saltara el modo local), arreglarlo aquí mismo.
- [ ] `cargo check -p xavier` y `cargo test -p xavier --lib provider` pasan.
