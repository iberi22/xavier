# [Ola 2 · 13] Docs: actualizar `LOCAL_SETUP.md` y `LOCAL_LLM_BRIDGES.md` con la guía 100% local post-Ola 2

> Parte de la iniciativa **Xavier 100% Local (LLM + embeddings vía Ollama) — Ola 2**.
> Issue de **documentación únicamente**. Sin cambios de código.

## 🎯 Contexto

Existen `docs/LOCAL_SETUP.md`, `docs/LOCAL_LLM_BRIDGES.md` y `docs/LOCAL_EMBEDDINGS.md`.
Estos docs fueron escritos antes de la Ola 2, cuando el chat del panel **no** usaba el LLM
local automáticamente. Tras la Ola 2 (issues 01–12), el flujo es:

> Instalar Ollama → `ollama pull qwen3-coder embeddinggemma` → `xavier serve` → el chat del
> panel usa local **automáticamente**, con fallback a cloud si se configura, y a memoria si
> todo falla.

Esa historia no está contada de punta a punta en ningún sitio.

## 📋 Problema

- Los docs actuales no reflejan el comportamiento de "local automático con fallback".
- Falta un quickstart unificado (Ollama + Xavier + verificar).
- No se menciona el modo degradado (memory-fallback) ni cómo leer el indicador de la UI (issues 07/08).

## ✅ Criterio de aceptación

- [ ] `docs/LOCAL_SETUP.md`: reescribir/añadir una sección **"Post-Ola 2: operación 100% local"** con:
  1. **Prerrequisitos:** Ollama instalado y corriendo (`ollama serve`).
  2. **Setup de 3 pasos:**
     ```bash
     ollama pull qwen3-coder
     ollama pull embeddinggemma
     xavier serve
     ```
  3. **Verificación:** el boot log debe mostrar `🟢 Xavier iniciado — modo: LOCAL | LLM: ollama/qwen3-coder [reachable] | Embeddings: ollama/embeddinggemma [reachable]` (issue 06). En la UI debe verse el badge 🦙 Local (issue 07).
  4. **Fallback:** si se configuran también providers cloud, la fallback chain los pone primero y local último (issue 04); al caer el cloud, salta a local automáticamente (issue 02).
  5. **Degradación:** si local también cae, el chat responde desde memoria con la nota 💾 (issues 03/08).
  6. **Troubleshooting:** `curl localhost:11434/api/tags` para validar Ollama; qué hacer si el badge dice ⚠️ Degradado; cómo cambiar de provider vía `/provider/set` (issue 10).
- [ ] `docs/LOCAL_LLM_BRIDGES.md`: actualizar para reflejar que el bridge openai-compatible
  hacia Ollama está **cableado por defecto** (issue 05), no es experimental. Documentar el
  contrato (base_url `http://localhost:11434/v1`, sin auth, modelo `qwen3-coder`).
- [ ] Enlazar desde `docs/LOCAL_SETUP.md` a `LOCAL_EMBEDDINGS.md` y a `ROADMAP_LOCAL_FIRST.md` (issue 14).
- [ ] Los valores de config mencionados deben coincidir **exactamente** con los del issue 12 (`XAVIER_MODEL_PROVIDER`, `XAVIER_LOCAL_LLM_MODEL`, etc.).
- [ ] Markdown linter (si hay configurado) pasa. Spell-check mínimo.
