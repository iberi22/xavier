# [Ola 2 · 08] UI Tauri: nota informativa cuando el chat cae a memory-fallback

> Parte de la iniciativa **Xavier 100% Local (LLM + embeddings vía Ollama) — Ola 2**.
> Trabajo frontend (React/TS). Es la contraparte visual del issue 03.

## 🎯 Contexto

El issue 03 (backend) hace que cuando **todos** los providers fallan, `/v1/chat` responda 200 con
una respuesta construida desde memoria, marcada con `provider: "memory-fallback"` en el cuerpo.
Sin este issue 08, el usuario vería esa respuesta como si fuera del LLM y se confundiría
("¿por qué me responde con notas raras?").

`panel-ui/src/components/ChatHistory.tsx` renderiza los mensajes del thread. Cada mensaje tiene
metadata (`PanelMessage` en `panel-ui/src/types.ts`). Hay que detectar el metadato y mostrar la
nota.

## 📋 Problema

Las respuestas de memory-fallback son indistinguibles de las del LLM en la UI actual. Falta
transparencia sobre el origen de cada respuesta.

## ✅ Criterio de aceptación

- [ ] `panel-ui/src/components/ChatHistory.tsx` (o el subcomponente que renderiza el mensaje assistant, p.ej. `StreamingMessageRenderer` / `MessageBubble`) detecta si el mensaje viene de memory-fallback:
  - Vía `message.metadata?.provider === "memory-fallback"` (supone que el backend popola metadata del mensaje — si el panel almacena mensajes con el campo metadata en JSON string, parsearlo; ver `panel_process_chat_inner` línea 159 que ya mete `metadata` como JSON).
  - Si el backend del issue 03 lo devuelve como campo top-level en `ChatResponse`, ajustar el tipo en `panel-ui/src/types.ts` para propagarlo hasta el mensaje guardado.
- [ ] Cuando se detecta, renderiza por encima del contenido del mensaje una **nota discreta**:
  > 💾 Respondiendo desde memoria (LLM no disponible)
  
  Estilo: fondo ámbar suave, ícono💾, tipografía chica. No debe tapar el contenido.
- [ ] La nota debe ser accesible (atributo `aria-label`) y no romper el modo streaming existente.
- [ ] Si el mensaje no tiene ese provider, cero cambios visuales (regresión segura).
- [ ] `npm run -w panel-ui build` y `lint` pasan.

```bash
cd panel-ui && npm run build && npm run lint
# En vivo:
# 1. Detener Ollama y cloud (forzar memory-fallback como en issue 03).
# 2. Enviar un mensaje en el panel.
# 3. La respuesta debe llevar la nota "💾 Respondiendo desde memoria".
# 4. Rearrancar Ollama, enviar otro mensaje → SIN la nota.
```

## 📎 Dependencias

- **Depende del issue 03** (backend) para que el campo `provider: "memory-fallback"` exista en la respuesta. Si 03 no está mergeado, el componente simplemente nunca muestra la nota (no rompe).
- Coordinar con issue 07 (ambos tocan `types.ts` en panel-ui — hacerlos en ramas distintas y mergear secuencialmente para evitar conflicto trivial).
- **NO crear archivos `.patch` / `.py` sueltos en la raíz del repo** (lección Ola 1, aplicada a frontend también).
