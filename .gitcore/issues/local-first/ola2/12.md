# [Ola 2 · 12] Configurar modelo de chat local por defecto en `xavier.config.json` y `.env.example`

> Parte de la iniciativa **Xavier 100% Local (LLM + embeddings vía Ollama) — Ola 2**.
> Issue de **configuración y documentación de variables** (sin lógica nueva).

## 🎯 Contexto

Hoy `config/xavier.config.json` ya tiene (líneas 48–60):

```json
"local_llm_url": "http://localhost:11434/v1",
"local_llm_model": "qwen3-coder",
...
"embedding_model": "embeddinggemma",
...
"local_llm_api_key": null,
```

Y `.env.example` (líneas 21–27):

```
# --- LOCAL-FIRST (Ollama) ---
# XAVIER_MODEL_PROVIDER=local
# XAVIER_LOCAL_LLM_URL=http://localhost:11434/v1
# XAVIER_LOCAL_LLM_MODEL=qwen3-coder
# XAVIER_EMBEDDING_PROVIDER_MODE=local
# XAVIER_EMBEDDING_MODEL=embeddinggemma
# OLLAMA_HOST=
```

Las vars existen pero están **comentadas** y falta: (a) asegurar que `provider="local"` sea el
default efectivo cuando nada más está seteado, (b) documentar `OLLAMA_HOST` y las vars relacionadas
al circuit breaker (issue 11) en una sección "local-first" coherente, (c) verificar que
`ModelProviderConfig::for_provider("local")` lee estos valores correctamente.

## 📋 Problema

Sin descomentar/asegurar estos defaults, el chat no usará local por defecto y el usuario tiene
que adivinar las variables.

## ✅ Criterio de aceptación

- [ ] En `config/xavier.config.json`, garantizar que existe un campo de nivel superior `provider` (o lo que `ModelProviderConfig::for_provider` lea como default) con valor `"local"`, **o** documentar en el archivo (comentario JSONC si el parser lo soporta, si no, en `LOCAL_SETUP.md` del issue 13) que `XAVIER_MODEL_PROVIDER=local` es el default recomendado post-Ola 2. Verificar cómo `config.rs` resuelve el provider default (`get_all_configured`, `for_provider`) antes de cambiar.
- [ ] Confirmar que `local_llm_model="qwen3-coder"` y `embedding_model="embeddinggemma"` son los valores efectivos que el proxy y el embedder leen cuando `provider=local`.
- [ ] En `.env.example`, **descomentar y completar** la sección local-first con comentarios explicativos (qué hace cada var, default, dónde leer más). Incluir:
  - `XAVIER_MODEL_PROVIDER=local`
  - `XAVIER_LOCAL_LLM_URL=http://localhost:11434/v1`
  - `XAVIER_LOCAL_LLM_MODEL=qwen3-coder`
  - `XAVIER_EMBEDDING_PROVIDER_MODE=local`
  - `XAVIER_EMBEDDING_MODEL=embeddinggemma`
  - `OLLAMA_HOST=127.0.0.1:11434` (con nota de que `ollama serve` ya lo respeta)
  - Mencionar `XAVIER_CB_FAILURES` y `XAVIER_CB_OPEN_SECS` del issue 11 si este se mergea antes (si no, dejar comentario `# (issue 11)`).
- [ ] Si al verificar se descubre que algún nombre de var difiere entre `.env.example` y el que `config.rs` lee realmente (p.ej. `XAVIER_LOCAL_LLM_MODEL` vs `LOCAL_LLM_MODEL`), alinearlos (preferir el que ya lee el código).
- [ ] `cargo check -p xavier` pasa (no debería requerir cambios de código, pero validar que el JSON sigue siendo parseable por el loader de config).
- [ ] Test de integración (en `tests/` o como test del loader de config) que cargue `config/xavier.config.json` y verifique `provider == "local"` y los campos `local_llm_*` presentes. Si el loader de config no tiene tests, dejar al menos un `#[test]` que valide el JSON parsea sin error y los campos existen.
