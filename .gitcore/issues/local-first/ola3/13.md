# [Ola 3 · 13] Script de smoke test local (CI manual)

> Parte de la iniciativa **Xavier 100% Local (LLM + embeddings vía Ollama) — Ola 3**.
> **No toca código Rust**. Solo un script en `scripts/`.

## 🎯 Contexto

Existen scripts de smoke ya:

- `scripts/release-smoke.sh` (185 líneas, bash): arranca contra un Xavier **ya corriendo** en
  `XAVIER_URL` y hace checks de `/health`, `/readiness`, `/memory/add`, `/memory/search`,
  `/v1/account/usage` y del panel. Usa `python3` para parsear JSON.
- `scripts/release-smoke.ps1` (equivalente PowerShell).
- `test-e2e-rag.sh` / `test-e2e-rag.ps1` (rag específico).

Lo que **falta**: un smoke script **self-contained** que:
1. **Arranca** el binario `xavier` (no asume que ya corre).
2. **Espera** al healthcheck con timeout.
3. Envía un **chat** vía `POST /panel/api/chat` o `/v1/chat/completions` (este último requiere
   menos setup — el panel necesita un thread preexistente).
4. Verifica respuesta **200** y que el body tenga `choices[0].message.content` no vacío (o que
   caiga a `memory-fallback` si no hay LLM, lo cual es 200 igual).
5. **Mata** el server al final (incluso si algo falla — `trap`).

Diseñado para CI manual (GitHub Actions step opcional, o pre-release local). No requiere
Ollama real (basta con que el memory-fallback o cualquier provider responda 200).

## 📋 Problema

No hay un "one-liner" que un operador pueda correr tras un `cargo build` para confirmar que
Xavier arranca, acepta chats y responde, sin levantar infra externa.

## ✅ Criterio de aceptación

- [ ] Crear **dos** archivos (cubrir Windows y Unix):
  - `scripts/smoke_test_local.sh` (bash, `set -euo pipefail`).
  - `scripts/smoke_test_local.ps1` (PowerShell equivalente, ` $ErrorActionPreference = "Stop"`).
- [ ] Flujo del script (ambos):
  1. Detectar el binario: `${XAVIER_BIN:-./target/debug/xavier}` o
     `${XAVIER_BIN:-./target/release/xavier}` según `XAVIER_BIN_ENV` (default debug).
  2. Generar token random si `XAVIER_TOKEN` no está seteado (`openssl rand -hex 16` o
     `$([guid]::NewGuid().ToString("N")`).
  3. Bind a puerto efímero (o `XAVIER_PORT` default `18006` para no chocar con el `8006`
     del dev).
  4. Spawn del binario con variables:
     `XAVIER_HOST=127.0.0.1`, `XAVIER_PORT=$PORT`, `XAVIER_TOKEN=$TOKEN`,
     `XAVIER_HEADLESS=true`,
     `XAVIER_CODE_GRAPH_DB_PATH=$TMP/xavier-smoke-code.db`,
     `XAVIER_MEMORY_VEC_PATH=$TMP/xavier-smoke-vec.db`,
     `XAVIER_MODEL_PROVIDER=${XAVIER_MODEL_PROVIDER:-local}` (para no forzar cloud),
     y capturar el PID.
  5. `trap` (bash) o `try/finally` (PS) para matar el PID al salir.
  6. Polling a `GET /health` hasta 200 con timeout 30s (bash: bucle `for i in {1..60}`;
     PS: bucle con `Start-Sleep -Seconds 1`).
  7. PEGAR a `POST /v1/chat/completions` con body:
     ```json
     {"model":"auto","messages":[{"role":"user","content":"ping"}]}
     ```
     y header `X-Xavier-Token: $TOKEN`.
  8. Asertar HTTP 200. Asertar que `choices[0].message.content` no es vacío (parsear con
     `python3 -c` o, si se quiere evitar la dependencia de Python, con `grep -o` sobre el
     raw — preferible Python para mantener el patrón de `release-smoke.sh`).
  9. Imprimir `PASS /v1/chat/completions` o `FAIL` con el body.
- [ ] En caso de fallo, volcar los últimos 50 líneas del log del server (stderr) a stdout
  para debug.
- [ ] Código de salida `0` si todo verde, `1` si cualquier paso falla.
- [ ] Documentar en `scripts/README.md` (si existe — verificar) o en el header del propio
  script cómo correrlo y qué variables acepta.

## 🧪 Cómo verificar

```bash
# Unix:
cargo build
bash scripts/smoke_test_local.sh
echo $?   # debe ser 0

# Windows (PowerShell):
cargo build
pwsh scripts/smoke_test_local.ps1
echo $LASTEXITCODE   # debe ser 0

# Con fallo intencional para validar el trap:
XAVIER_BIN=/bin/false bash scripts/smoke_test_local.sh
echo $?   # debe ser 1 y no dejar proceso colgado
```
