# [Ola 3 · 06] Guía de usuario final 100% local

> Parte de la iniciativa **Xavier 100% Local (LLM + embeddings vía Ollama) — Ola 3**.
> **Solo docs**. No toca código.

## 🎯 Contexto

Existen docs técnicos (`docs/ROADMAP_LOCAL_FIRST.md`, referencias a `docs/LOCAL_SETUP.md`,
`docs/LOCAL_LLM_BRIDGES.md`, `docs/LOCAL_EMBEDDINGS.md`) pero están orientados a
desarrolladores. No hay una **guía paso a paso para usuario final** que cubra el flujo completo:
instalar Ollama → pull modelos → `xavier setup --local` → `xavier serve` → abrir panel →
chatear, con troubleshooting y FAQ.

El wizard `xavier setup --local` ya existe (`src/cli/handlers/setup.rs:166`) y hace la mayoría
del cableado automáticamente (detecta Ollama, sugiere pull de modelos, escribe config). El
panel UI abre en `http://localhost:8006/panel` y tiene badge de modo (PR #567) y nota de
memory-fallback (PR #566).

## 📋 Problema

1. Un usuario final que quiera "Xavier 100% local, sin nube" no tiene un único documento que
   seguir.
2. Faltan troubleshooting (Ollama no arranca, modelo no se baja, puerto ocupado, embedding
   dim mismatch) y FAQ.

## ✅ Criterio de aceptación

- [ ] Crear `docs/USER_GUIDE_LOCAL.md` con esta estructura:
  1. **Prerrequisitos**: hardware recomendado (RAM, GPU opcional), SO soportados, Docker o
     nativo.
  2. **Paso 1 — Instalar Ollama**: link a https://ollama.com, instrucciones Windows/macOS/
     Linux, verificación (`ollama --version`).
  3. **Paso 2 — Descargar modelos**: `ollama pull qwen3-coder` (LLM) y
     `ollama pull embeddinggemma` (embeddings). Tabla con alternativas (modelos más chicos
     para hardware limitado, con la dimensión de embedding que cada uno exige).
  4. **Paso 3 — Instalar Xavier**: `cargo install --path .` o binario release.
  5. **Paso 4 — Configurar**: `xavier setup --local` (explicar qué hace el wizard:
     detecta Ollama, valida reachability, escribe `config/xavier.config.json` y `.env`).
  6. **Paso 5 — Arrancar**: `xavier http 8006` (o `xavier serve` — verificar nombre real del
     subcomando: en `enums.rs` la variante es `Http`, pero el alias `serve` puede existir).
  7. **Paso 6 — Abrir el panel**: `http://localhost:8006/panel`, iniciar sesión con el token.
  8. **Paso 7 — Chatear**: explicar que el badge de modo debe decir "local" (verde). Si dice
     "degradado" o cae a memory-fallback, ir al troubleshooting.
  9. **Docker alternativo**: referencia cruzada al issue 05 (`docker/docker-compose.local.yml`).
- [ ] Sección **Troubleshooting** con al menos estos casos:
  - "Ollama no arranca" (puerto 11434 ocupado, GPU drivers).
  - "El chat cae siempre a memory-fallback" (modelo no instalado, URL mal en config —
    sugerir `xavier doctor`).
  - "Búsqueda semántica da resultados raros tras cambiar de modelo de embedding" (referencia
    al issue 02 y a `POST /memory/reindex`).
  - "Quiero volver a modo cloud" (`xavier setup` sin `--local`, o editar config).
  - "El panel dice 401" (token incorrecto — cómo resetearlo).
- [ ] Sección **FAQ** (mínimo 6 preguntas):
  - ¿Necesito GPU? (no, pero recomendado para qwen3-coder).
  - ¿Funciona offline? (sí, una vez descargados los modelos).
  - ¿Cuánto espacio en disco? (~5 GB entre los dos modelos + DB).
  - ¿Puedo usar otro LLM? (sí, cualquier modelo Ollama — cambiar `XAVIER_LOCAL_LLM_MODEL`).
  - ¿Mis datos salen de mi máquina? (no en modo local).
  - ¿Cómo actualizo un modelo? (`ollama pull` de nuevo).
- [ ] **Capturas conceptuales**: ASCII o mermaid del flujo
  `panel → /panel/api/chat → ProxyUseCase → Ollama (local) → respuesta`, mostrando las ramas
  fallback (cloud → memory). No hace falta imagen real; un diagrama ASCII/Mermaid es suficiente.
- [ ] Linkar desde `docs/ROADMAP_LOCAL_FIRST.md` (sección "Enlaces de Interés") y desde
  `README.md` (sección de quickstart local si existe).
