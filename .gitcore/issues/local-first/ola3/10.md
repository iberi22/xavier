# [Ola 3 · 10] Test E2E del chat con fallback a memoria (sin Ollama real)

> Parte de la iniciativa **Xavier 100% Local (LLM + embeddings vía Ollama) — Ola 3**.

## 🎯 Contexto

Existen tests E2E que arrancan el binario completo de Xavier:

- `tests/server_e2e.rs` (usando `std::process::Command::new(env!("CARGO_BIN_EXE_xavier"))`,
  patrón `ChildGuard` con `Drop` que mata el server).
- `tests/headless_chat_test.rs` (mismo patrón; arranca headless en puerto efímero, espera
  `/health` con polling de 30 intentos × 500ms, luego pega a `/v1/chat/completions`).

El endpoint de chat headless es `POST /v1/chat/completions` → `headless_chat`
(`src/cli/handlers/headless_api.rs:106`). Su flujo (tras Ola 2):

1. Llama `state.proxy_use_case.execute_secured(cmd, ...)`.
2. Si OK → responde 200 con el `ChatCompletion`.
3. Si `Err(e)` → entra la rama de memory-fallback (líneas ~144+ de `headless_api.rs`):
   - Extrae el último mensaje del usuario.
   - Llama `state.memory.search(query, 5, None).await`.
   - Si hay resultados, sintetiza una respuesta con `provider = "memory-fallback"` y
     `model = "memory-fallback"`, prefijo `[Modo memoria — LLM no disponible]`.

> **Divergencia conocida:** el diff del PR #574 añadió `fallback_from_memory`, pero el
> PR #568 posterior lo **removió** al refactorizar `headless_api.rs`. Verificar el estado
> real en `src/cli/handlers/headless_api.rs` antes de escribir el test: si `fallback_from_memory`
> no existe, el test debe enfocarse en el **flujo de fallback entre providers** dentro de
> `ProxyUseCase` (`handle_provider_fallback`) en su lugar, o documentar que el memory-fallback
> necesita restaurarse primero.

Para forzar el fallo del provider sin Ollama real, basta con apuntar
`XAVIER_LOCAL_LLM_URL` a un endpoint inexistente (p.ej. `http://127.0.0.1:1/v1`) y dejar
todos los cloud sin API key — así `execute_secured` devuelve `ProxyError::RateLimited` o
`ProviderError`, disparando el memory-fallback.

## 📋 Problema

No hay un test automático que verifique el happy-path de resiliencia:
"LLM cae → memoria responde → usuario no ve error 500". Hoy solo se valida manualmente.
