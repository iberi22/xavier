# [Ola 3 · 11] Log estructurado y rotación — auditoría y gaps

> Parte de la iniciativa **Xavier 100% Local (LLM + embeddings vía Ollama) — Ola 3**.

## 🎯 Contexto

La base ya está implementada en `src/observability/mod.rs:54-106`:

```rust
use tracing_appender::rolling::{RollingFileAppender, Rotation};
use tracing_subscriber::{fmt, layer::SubscriberExt, util::SubscriberInitExt, EnvFilter, Registry};

pub fn init_logger(log_dir: &Path, level: &str) {
    let filter = EnvFilter::try_from_env("XAVIER_LOG").unwrap_or_else(|_| EnvFilter::new(level));
    let file_appender = RollingFileAppender::new(Rotation::DAILY, log_dir, "xavier");
    let (non_blocking, guard) = tracing_appender::non_blocking(file_appender);
    Registry::default()
        .with(filter)
        .with(fmt::Layer::new().json().with_target(true).with_file(true)
              .with_line_number(true).with_writer(non_blocking))
        .with(fmt::Layer::new().with_target(true).with_level(true).compact())
        .init();
}
```

Y se invoca desde `src/main.rs:60` con `log_dir = $HOME/.xavier/logs` (o `XAVIER_LOG_DIR`).

**Gaps reales** que sí faltan:

1. **Sin retención**: `RollingFileAppender::new(Rotation::DAILY, ...)` crea un fichero por día
   pero **nunca borra los antiguos**. Tras meses, el disco se llena. El doc-comment de
   `init_logger` (línea 56 del mod) dice "max 30 files retained" pero el código **no aplica**
   esa retención — es solo una afirmación. Hay que añadir limpieza real (un `tokio::spawn` que
   corra diariamente, o un cleanup best-effort al arranque).
2. **Sin log del modo local al boot**: tras el health-check de Ollama (#564), debería
   registrarse en el log estructurado (JSON) un evento `boot.local_mode = {provider, model,
   ollama_reachable}` que un dashboard pueda parsear. Hoy solo hay `info!` ad-hoc.
3. **El guard es `[WorkerGuard; 1]`** (línea 58) — funciona, pero no expone hook para
   `shutdown`/`flush` ordenado en `main.rs` antes de salir.

## 📋 Problema

1. Los logs crecen indefinidamente (un fichero `xavier.YYYY-MM-DD` por día, sin límite).
2. El boot no deja un evento estructurado estándar que diga "arranqué en modo local X con
   reachability Y".

## ✅ Criterio de aceptación

- [ ] **Retención de logs** en `src/observability/mod.rs`:
  - Añadir una función `purge_old_logs(log_dir: &Path, max_age_days: u32)` que liste los
    ficheros `xavier.*` y borre los más antiguos que `max_age_days` días (comparando por
    `mtime` o parseando el sufijo de fecha del `RollingFileAppender`, que tiene formato
    `xavier.YYYY-MM-DD`).
  - Llamarla una vez al final de `init_logger` (best-effort, sin propagar errores).
  - Hacerla configurable vía `XAVIER_LOG_RETENTION_DAYS` (default 30, para cumplir la
    promesa del doc-comment).
  - Loguear con `tracing::info!` cuántos ficheros purgó (después de inicializar el subscriber).
- [ ] **Evento de boot estructurado**: tras la inicialización del logger en
  `src/main.rs:60`, añadir un `tracing::info!` estructurado:
  ```rust
  tracing::info!(
      target: "xavier::boot",
      event = "boot",
      version = env!("CARGO_PKG_VERSION"),
      mode = %xavier::server::alerts::SYSTEM_ALERTS.get_mode(),
      provider = std::env::var("XAVIER_MODEL_PROVIDER").unwrap_or_default(),
      llm_model = std::env::var("XAVIER_LOCAL_LLM_MODEL").unwrap_or_default(),
      embedding_model = std::env::var("XAVIER_EMBEDDING_MODEL").unwrap_or_default(),
      log_dir = %log_dir.display(),
      "Xavier boot complete"
  );
  ```
  (Si `SYSTEM_ALERTS.get_mode()` aún no está poblado al arranque, llamarlo después de que
  `cli.run()` configure el router, o mover este log al final de `start_http_server` en
  `src/cli/server.rs` cerca de la línea 86 donde ya se llama `HEALTH.run_checks().await`.)
- [ ] **Doc real**: corregir el doc-comment de `init_logger` (línea 56) para reflejar que la
  retención es `XAVIER_LOG_RETENTION_DAYS` (default 30) y documentar las variables de env
  soportadas (`XAVIER_LOG_DIR`, `XAVIER_LOG_LEVEL`, `XAVIER_LOG`, `XAVIER_LOG_RETENTION_DAYS`).
- [ ] Test unitario para `purge_old_logs`: crear un `tempdir`, meter 3 ficheros
  `xavier.2026-01-0N` con mtimes viejos, llamar con `max_age_days = 1`, y verificar que se
  borran los viejos pero no los recientes.
- [ ] `cargo check --workspace` y `cargo test -p xavier --lib observability` pasan.
