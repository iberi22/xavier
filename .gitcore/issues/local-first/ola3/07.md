# [Ola 3 · 07] Endpoint `/health` enriquecido

> Parte de la iniciativa **Xavier 100% Local (LLM + embeddings vía Ollama) — Ola 3**.

## 🎯 Contexto

`headless_health` (`src/cli/handlers/headless_api.rs:25`) actualmente devuelve:

```rust
AxumJson(json!({
    "status": status.status,
    "mode": status.mode,
    "service": "xavier-headless",
    "version": env!("CARGO_PKG_VERSION"),
    "llm": status.llm,
    "embeddings": status.embedding,
    "vector_db": status.vector_db,
}))
```

donde `status` es un `HealthStatus` de `crate::observability::health::HEALTH.get_status().await`
(`src/observability/health.rs:190`). El struct `HealthStatus` (líneas 84-95) ya contiene
`mode`, `llm: LlmHealth { provider, model, endpoint, reachable, status }`,
`embedding: EmbeddingHealth { provider, model, latency_ms, error_rate, status }`,
`vector_db: VectorDbHealth { backend, path, status }`, `system` y `database`.

**Lo que falta vs. lo pedido en este issue** (`{mode, llm:{provider,model,reachable},
embeddings:{model,reachable}, vector_db, uptime}`):

1. **`uptime`** no se expone. `SystemHealth` (`health.rs:28-33`, inferido) tiene `uptime_secs`
   pero no se incluye en la respuesta JSON de `headless_health`.
2. La forma actual anida los objetos completos (`status.llm` con `endpoint`, `latency_ms`,
   etc.) que está bien, pero el consumidor típico (panel UI, `xavier doctor`, scripts) quiere
   una **forma aplanada y predecible** con los campos críticos siempre presentes:
   `mode`, `llm.{provider,model,reachable}`, `embeddings.{model,reachable}`,
   `vector_db.{backend,path,status}`, `uptime_secs`.

`OperationalMode` (`src/server/alerts.rs:7-12`) serializa en kebab-case:
`local-healthy` / `local-degraded` / `cloud-fallback` / `disabled`. Eso es el `mode`.

## 📋 Problema

1. Falta `uptime` en `/health`.
2. La forma del payload no está documentada como contrato estable — los consumidores tienen
   que adivinar qué subcampos existen.
