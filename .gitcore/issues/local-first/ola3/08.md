# [Ola 3 · 08] MCP server: exponer estado de modo local como tool

> Parte de la iniciativa **Xavier 100% Local (LLM + embeddings vía Ollama) — Ola 3**.

## 🎯 Contexto

El MCP server vive en `src/server/mcp/`. El registro de tools se hace en
`src/server/mcp/server.rs:10` (`get_xavier_tools`) que concatena tres conjuntos:

```rust
pub fn get_xavier_tools() -> Vec<MCPTool> {
    let mut tools = super::tools_core::get_xavier_core_tools();
    tools.extend(super::tools_memory::get_xavier_memory_tools());
    tools.extend(super::tools_context::get_xavier_context_tools());
    tools
}
```

Cada conjunto:
- `tools_core::get_xavier_core_tools()` (`src/server/mcp/tools_core.rs:16`) declara tools como
  `list_projects`, `get_project_context`, `sync_gitcore`, `health_check`, `get_code_graph`.
- `is_core_tool(name)` (línea 88) decide el dispatch.
- `handle_core_tool(state, workspace, name, arguments)` (línea 99) ejecuta la tool por nombre.
- `handle_tool_call` (`server.rs:37`) enruta entre `core` / `context` / `memory`.

Ya existe una tool `health_check` (línea 70) que devuelve `HealthStatus` completo vía
`MCPToolResult::structured`. Pero un agente MCP externo que consume Xavier quiere una tool
**focalizada en el modo local** que devuelva:
- `mode` (`local-healthy` / `local-degraded` / `cloud-fallback` / `disabled` —
  `OperationalMode` de `src/server/alerts.rs:7`).
- `provider_setting` (lo que el usuario configuró, p.ej. `local`).
- `llm_reachable` (bool).
- `embedding_reachable` (bool).
- `fallback_chain` (lista de providers en orden).
- `ollama_reachable` (bool).

Esto permite a un agente que orquesta sobre MCP decidir "¿puedo delegar razonamiento a Xavier
o está caído?".

`OperationalMode::derive_operational_mode` (`alerts.rs:66`) y `ProviderRouter::fallback_chain`
(`router.rs`, expuesto vía el headless handler en `headless_api.rs:162`) ya están.

## 📋 Problema

No hay tool MCP específica para "¿está Xavier en modo local y operativo?". El agente tendría
que llamar `health_check` y parsear el struct completo, que es ruidoso.

## ✅ Criterio de aceptación

- [ ] Añadir a `get_xavier_core_tools()` (`src/server/mcp/tools_core.rs:16`, al final del
  `vec![...]`) una nueva `MCPTool`:
  ```rust
  MCPTool {
      name: "xavier_local_status".to_string(),
      description: "Report Xavier local-first operation mode and reachability \
                    (local/cloud/degraded, Ollama reachable, fallback chain).".to_string(),
      input_schema: json!({ "type": "object", "properties": {} }),
  },
  ```
- [ ] Añadir `"xavier_local_status"` al matcher en `is_core_tool` (línea 88-97).
- [ ] En `handle_core_tool` (línea 99), añadir un brazo:
  ```rust
  "xavier_local_status" => {
      let mode = crate::server::alerts::SYSTEM_ALERTS.get_mode();
      let provider = std::env::var("XAVIER_PROVIDER")
          .or_else(|_| std::env::var("XAVIER_MODEL_PROVIDER"))
          .unwrap_or_else(|_| "local".into());
      // Reuse reachability from HEALTH or from ModelProviderConfig::is_reachable
      let health = crate::observability::health::HEALTH.get_status().await;
      Ok(serde_json::to_value(MCPToolResult::structured(json!({
          "mode": mode,
          "provider_setting": provider,
          "llm_reachable": health.llm.reachable,
          "embedding_reachable": health.embedding.status != crate::observability::health::HealthLevel::Unhealthy,
          "fallback_chain": [],        // si no hay acceso al router aquí, omitir o dejar []
          "ollama_reachable": health.llm.reachable && (provider == "local" || provider == "ollama"),
      })))?)
  }
  ```
  Nota: `handle_core_tool` recibe `_state: AppState` (línea 100) que **no** incluye
  `provider_router` (ese está en `CliState`, no en `AppState` — ver `src/lib.rs:66`). Por eso
  `fallback_chain` puede quedar `[]` o, si se quiere poblar, expponer el router en `AppState`.
  **Decisión de scope:** para este issue basta con exponer `mode` + reachability; si hace
  falta el `fallback_chain`, dejar un `// TODO: requires AppState.provider_router`.
- [ ] Si `MCPToolResult::structured` no existe con esa firma, mirar cómo lo usa el brazo
  existente de `health_check` (línea ~213, 229, 333) y replicar el patrón exacto.
- [ ] Test: añadir caso en `src/server/mcp/tests.rs` que llame a la tool y verifique que
  devuelve `mode` como uno de los cuatro valores válidos.
- [ ] `cargo check --workspace` y `cargo test -p xavier --lib mcp` pasan.
