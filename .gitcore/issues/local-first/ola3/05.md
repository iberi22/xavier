# [Ola 3 · 05] Docker compose con Ollama (100% local en un solo comando)

> Parte de la iniciativa **Xavier 100% Local (LLM + embeddings vía Ollama) — Ola 3**.
> **No toca código Rust**. Solo infra + docs.

## 🎯 Contexto

El directorio `docker/` ya contiene varios `docker-compose*.yml` (embeddings, benchmarks,
cortex-enterprise, etc.) y un `Dockerfile` principal en la raíz del repo. **No existe** un
compose que levante a la vez **Ollama + Xavier** con healthcheck y auto-pull de los modelos
`qwen3-coder` (LLM) y `embeddinggemma` (embeddings).

La config local de Xavier espera:
- `XAVIER_LOCAL_LLM_URL=http://localhost:11434/v1`
- `XAVIER_EMBEDDING_URL=http://localhost:11434/api/embeddings`
- `XAVIER_MODEL_PROVIDER=local`
- `XAVIER_LOCAL_LLM_MODEL=qwen3-coder`
- `XAVIER_EMBEDDING_MODEL=embeddinggemma`

(Valores escritos por `handle_local_setup` en `src/cli/handlers/setup.rs:238-243`.)

El health endpoint de Xavier es `GET /health` (`src/cli/handlers/headless_api.rs:25`,
`headless_health`), y el de Ollama es `GET /api/version`. El puerto por defecto de Xavier es
`8006` (`XAVIER_PORT`).

## 📋 Problema

Hoy, correr Xavier 100% local en Docker requiere levantar Ollama a mano, hacer `ollama pull`
de los dos modelos, configurar variables, y luego arrancar Xavier. Un usuario final se pierde.

## ✅ Criterio de aceptación

- [ ] Crear `docker/docker-compose.local.yml` con dos servicios:
  - **`ollama`**: imagen oficial `ollama/ollama:latest`, volumen persistente
    `ollama_models:/root/.ollama`, puerto `11434:11434`, healthcheck cada 30s contra
    `http://localhost:11434/api/version` (start-period 10s, retries 5).
  - **`xavier`**: build desde el `Dockerfile` raíz (o `docker/Dockerfile.public`), depende de
    `ollama` (condition: `service_healthy`), variables de entorno para apuntar a Ollama:
    ```yaml
    environment:
      XAVIER_MODEL_PROVIDER: local
      XAVIER_LOCAL_LLM_URL: http://ollama:11434/v1
      XAVIER_EMBEDDING_URL: http://ollama:11434/api/embeddings
      XAVIER_LOCAL_LLM_MODEL: qwen3-coder
      XAVIER_EMBEDDING_MODEL: embeddinggemma
      XAVIER_HOST: 0.0.0.0
      XAVIER_PORT: 8006
      XAVIER_TOKEN: ${XAVIER_TOKEN:-local-dev-token}
    ports: ["8006:8006"]
    healthcheck: GET /health cada 30s.
    ```
- [ ] Añadir un **one-shot** `ollama-pull` (servicio con `profiles: ["init"]` o entrypoint
  custom) que corra `ollama pull qwen3-coder` y `ollama pull embeddinggemma` contra el host
  Ollama y termine, para que el usuario pueda hacer:
  `docker compose -f docker/docker-compose.local.yml --profile init run ollama-pull`.
  Alternativamente, documentar el `ollama pull` manual en la doc.
- [ ] Crear `docs/LOCAL_SETUP.md` con una sección **"Docker (todo en uno)"** que muestre:
  ```bash
  export XAVIER_TOKEN=mi-token
  docker compose -f docker/docker-compose.local.yml up -d
  # (opcional, primera vez) docker compose -f docker/docker-compose.local.yml --profile init run ollama-pull
  curl http://localhost:8006/health
  ```
  Si `docs/LOCAL_SETUP.md` ya existe (verificar — está referenciado en `ROADMAP_LOCAL_FIRST.md`
  pero podría no existir), añadir la sección al final sin reescribir el resto.
- [ ] Incluir un `.env.docker.example` (en `docker/`) con `XAVIER_TOKEN=` comentado.
- [ ] Validar sintaxis: `docker compose -f docker/docker-compose.local.yml config` no da error.

## 🧪 Cómo verificar

```bash
docker compose -f docker/docker-compose.local.yml config > /dev/null && echo "syntax ok"
# En una máquina con Docker:
export XAVIER_TOKEN=mi-token
docker compose -f docker/docker-compose.local.yml up -d
sleep 30
curl -sf http://localhost:11434/api/version        # Ollama ok
curl -sf http://localhost:8006/health              # Xavier ok
docker compose -f docker/docker-compose.local.yml down -v
```
