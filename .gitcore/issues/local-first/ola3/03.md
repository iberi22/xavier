# [Ola 3 · 03] Métricas de uso reales: tokens, providers usados, fallback hits

> Parte de la iniciativa **Xavier 100% Local (LLM + embeddings vía Ollama) — Ola 3**.

## 🎯 Contexto

Existen **dos** endpoints que devuelven datos de uso, ambos parcialmente stub:

1. `/v1/account/usage` → `account_usage_handler` (`src/cli/handlers/usage.rs:16`, montado en
   `src/cli/server.rs:441`). Devuelve `provider_quotas` reales (vía
   `rate_manager.get_all_providers()`) pero con campos como `document_count: 0`,
   `requests_used: 0`, `optimization.semantic_cache_hits: 0` **hardcodeados a 0**.
2. `headless_usage` (`src/cli/handlers/headless_api.rs:283`) que devuelve JSON completamente
   inventado (`today.requests: 222`, `tokens: 870_000`, ...). Está montado en
   `src/cli/server.rs:631` pero no parece tener ruta propia — verificar.

El único lugar donde se cuentan tokens es `ProxyUseCase::execute_secured`
(`src/app/proxy_use_case.rs`):
- Éxito: `rate_manager.track_request(&provider_name, total_tokens, 200, cost_usd, is_cache_hit)`
  en línea 477-483.
- Timeout interno: `track_request(..., 0, 504, 0.0, false)` en línea 538-544.
- Fallo 500: `track_request(..., 0, 500, 0.0, false)` en línea 567-573.
- Timeout externo: `track_request(..., 0, 504, 0.0, false)` en línea 594-600.

`track_request` (`src/agents/provider/rate_limit.rs:107`) ya persiste `(provider, status,
tokens, cost, is_cache_hit, timestamp)` en la tabla `provider_quotas` (o `request_log` si
existe — verificar el SQL en líneas 141-145). Por lo tanto los datos **ya están en SQLite**.
Lo que falta es **agregarlos** y exponerlos.

Además, el fallback a memoria (PR #574) **no se cuenta**: cuando `headless_chat` cae a
`fallback_from_memory` no se trackea nada. Y los `fallback_chain` hops dentro de
`handle_provider_fallback` (`proxy_use_case.rs:68-94`) tampoco.

## 📋 Problema

1. `/v1/account/usage` miente (ceros hardcodeados) → no se puede monitorear uso real.
2. No hay visibilidad de cuántas respuestas cayeron a `memory-fallback` vs LLM real.
3. No hay contador de cuántas veces saltó el `fallback_chain` entre providers.

## ✅ Criterio de aceptación

- [ ] Añadir a `ProxyUseCase` (`src/app/proxy_use_case.rs:26-33`) un campo de contadores
  compartido:
  ```rust
  pub usage_counters: Arc<crate::observability::UsageCounters>,
  ```
  Donde `UsageCounters` es un struct nuevo (en `src/observability/` o en `src/app/`) con un
  `parking_lot::RwLock<UsageSnapshot>` (patrón similar a `prompt_cache`):
  ```rust
  pub struct UsageCounters { inner: RwLock<UsageSnapshot> }
  pub struct UsageSnapshot {
      pub by_provider: HashMap<String, ProviderUsage>,
      pub memory_fallback_hits: u64,
      pub fallback_chain_hops: u64,
      pub total_tokens: u64,
      pub total_cost_usd: f64,
  }
  pub struct ProviderUsage { requests: u64, tokens: u64, errors: u64, cost_usd: f64 }
  ```
  Exponer `UsageCounters::new()`, `record_success(provider, tokens, cost)`,
  `record_error(provider)`, `record_memory_fallback()`, `record_fallback_hop()`,
  `snapshot() -> UsageSnapshot` (clone barata).
- [ ] Llamar a los contadores en `execute_secured` (junto a `track_request`):
  - Éxito (línea ~477): `self.usage_counters.record_success(&provider_name, total_tokens as u64, cost_usd)`.
  - Fallo (líneas ~538, ~567, ~594): `self.usage_counters.record_error(&provider_name)`.
  - En `handle_provider_fallback` (línea 83, dentro del `if let Some(next_kind)`):
    `self.usage_counters.record_fallback_hop()`.
- [ ] Inicializar `usage_counters` en `ProxyUseCase::new` (línea 36) y propagarlo desde
  `CliState` (`src/cli/state.rs:66` — añadir campo `pub usage_counters: Arc<UsageCounters>`)
  para que el handler pueda leerlo.
