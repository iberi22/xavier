# [Ola 3 · 09] Bot Telegram: comando `/localstatus`

> Parte de la iniciativa **Xavier 100% Local (LLM + embeddings vía Ollama) — Ola 3**.

## 🎯 Contexto

El bot de Telegram vive en `src/telegram/mod.rs` (1063 líneas). El enum `Command`
(`src/telegram/mod.rs:105-131`) declara los slash commands con `#[derive(BotCommands)]`:

```rust
pub enum Command {
    Help, Start, Health, Stats,
    Search(String), Add(String), Scan(String), Agents,
    Memory(String),
}
```

El handler es `XavierBot::handle_command` (línea 431) y despacha con `match cmd` (ver
`Command::Health => { ... }` en línea 474, que hoy devuelve un mensaje **hardcodeado**
"Xavier System Status / Service: Online / Version / Bot: Connected" — no consulta nada real).

El tipo `OperationalMode` (`src/server/alerts.rs:7`) tiene los cuatro modos serializables en
kebab-case (`local-healthy`, `local-degraded`, `cloud-fallback`, `disabled`).

## 📋 Problema

1. El comando `/health` existente miente (siempre dice "Online"). No refleja el modo local ni
   si Ollama está reachable.
2. No hay un comando específico que un operador pueda invocar desde Telegram para saber
   "¿está Xavier corriendo 100% local o se degradó?".
