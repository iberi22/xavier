# ISSUE: Headless Mode — TCP/HTTP API para CLI Agents Externos

**Type**: feature | **Labels**: backend, api, integration | **Priority**: P1 | **Points**: 8

## Context
Con headless mode habilitado, Xavier expone API HTTP en puerto configurable (default 8007) donde CLI agents externos (opencode, codex, claude, copilot) consultan contexto QMD, ejecutan tools, y obtienen provider status.

## Endpoints

### GET /health
`{"status": "ok", "version": "0.6.1-beta"}`

### GET /context?query=<text>&limit=<n>
QMD memory search → contexto relevante
`{"items": [...], "total": n}`

### POST /memory/search
```json
{"text": "query", "limit": 10, "filters": {"namespace": "codebase"}}
```
`{"results": [...], "total": n}`

### GET /tools
Lista de herramientas disponibles:
`{"tools": [{"name": "memory_search", "params": {...}}]}`

### POST /tools/:name
Ejecuta una tool:
```json
{"args": {"query": "search", "limit": 5}}
```
`{"result": {...}, "execution_time_ms": 123}`

### GET /provider/status
Provider activo + available + quota:
`{"active": "ollama", "available": ["ollama", "openai"], "quota": {...}}`

## Auth
- Header `Authorization: Bearer <token>`
- Token de `~/.xavier/provider-config.yaml` o env `XAVIER_TOKEN`
- Solo localhost (127.0.0.1)

## Security
- Bind solo a 127.0.0.1
- Rate limit 60 req/min por cliente
- Logging completo (IP, endpoint, timestamp)
- Nunca exponer API keys en responses

## CLI Commands
- `xavier headless enable` → activa
- `xavier headless disable` → desactiva
- `xavier headless status` → running? puerto? requests?
- `xavier headless token generate` → nuevo token
