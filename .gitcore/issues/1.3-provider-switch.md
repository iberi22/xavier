# ISSUE: Hot-switch Provider System

**Type**: feature | **Labels**: backend, routing | **Priority**: P1 | **Points**: 3

## Context
El usuario debe poder cambiar de proveedor LLM en caliente (sin reiniciar Xavier). También configurar una cadena de fallback por si el proveedor primario falla.

## Core Model
```rust
pub enum ActiveProvider {
    Auto { strategy: AutoStrategy },
    Manual(ProviderKind),
    Fallback(Vec<ProviderKind>),
}

pub enum AutoStrategy {
    LowestLatency,
    LowestCost,
    BestQuality,
    DeterministicOnly,
}

pub struct ProviderRouter {
    active: ActiveProvider,
    fallback_chain: Vec<ProviderKind>,
    current_provider: ProviderKind,
    switch_history: Vec<ProviderSwitchEvent>,
}

impl ProviderRouter {
    pub fn switch_to(&mut self, provider: ProviderKind) -> Result<()>;
    pub fn set_auto_strategy(&mut self, strategy: AutoStrategy);
    pub fn set_fallback_chain(&mut self, providers: Vec<ProviderKind>);
    pub fn on_provider_failure(&mut self) -> Option<ProviderKind>;
}
```

## CLI Commands
- `xavier provider set <name>` → cambia en caliente
- `xavier provider status` → muestra activo + fallback
- `xavier provider list` → lista todos disponibles
- `xavier provider auto <strategy>` → configura auto-strategy

## Integration
- Router se integra con `src/agents/provider/client.rs`
- Handlers LLM obtienen provider activo del router
- Si activo falla, recorre fallback chain automáticamente
