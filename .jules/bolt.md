## 2024-05-19 - [Extract inline map callback into memoized component to prevent O(N) re-renders]
**Learning:** In React components displaying lists (like DAO proposals), changing the state of a single list item (such as casting a vote which updates `submittingVoteId` and `localProposals`) can trigger a full re-render of the parent component and ALL list items if they are rendered inline inside a `.map()`. This results in an O(N) performance bottleneck during user interactions with list items.
**Action:** Always extract complex inline elements within `.map()` callbacks into separate components and wrap them in `React.memo()`. This ensures that only the specific item whose props have changed will re-render, reducing the operation from O(N) to O(1) and significantly improving interaction latency.
## 2024-05-19 - [Extract inline map callback into memoized component to prevent O(N) re-renders]
**Learning:** In React components displaying chat lists (like P2P messaging), typing in an input field mapped to a parent state variable (like `inputText`) can cause the entire component and ALL child elements rendered inline inside a `.map()` to re-render. This causes O(N) performance degradation during fast interactions like typing. Also, unmemoized arrays defined by `.filter` will run N iterations on every render.
**Action:** Always extract complex elements rendered within `.map()` into separate components and wrap them in `React.memo()`. Always wrap array filters based on state/props in `useMemo()` to guarantee they only execute when dependencies change. This reduces O(N) rendering and calculations to O(1).
