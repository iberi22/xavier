## 2024-05-19 - [Extract inline map callback into memoized component to prevent O(N) re-renders]
**Learning:** In React components displaying lists (like DAO proposals), changing the state of a single list item (such as casting a vote which updates `submittingVoteId` and `localProposals`) can trigger a full re-render of the parent component and ALL list items if they are rendered inline inside a `.map()`. This results in an O(N) performance bottleneck during user interactions with list items.
**Action:** Always extract complex inline elements within `.map()` callbacks into separate components and wrap them in `React.memo()`. This ensures that only the specific item whose props have changed will re-render, reducing the operation from O(N) to O(1) and significantly improving interaction latency.

## 2025-02-23 - [Extract handlers passed to memoized components into useCallback]
**Learning:** In React components rendering lists of items that are wrapped in `React.memo()` (like `NotificationItem` and `ToastBanner` in `NotificationCenter`), if the callback handlers (`markRead`, `dismissNotification`, etc.) passed to them are not wrapped in `React.useCallback`, new function references are created on every render. This completely defeats the `React.memo()` check, causing all list items to re-render (an O(N) operation) whenever the parent component state updates.
**Action:** Always wrap event handlers that are passed down to memoized child components in `React.useCallback` with the proper dependency array (often empty `[]` when relying on functional state updates like `setNotifications(prev => ...)`). This ensures referential equality and preserves the O(1) update behavior during list interactions.
