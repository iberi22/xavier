This PR introduces the skill-controller security review checklist and a static guard script, implementing the invariants defined in WAVE-1012.11 (O04 / #2623).

### What Changed
- Added `scripts/skill-controller-guards.sh` to enforce the 5 security invariants (D4, D10-D14) using static `awk`/`grep` analysis, correctly stripping `#[cfg(test)]` blocks.
- Added `scripts/tests/skill-controller-guards-test.sh` to provide comprehensive test coverage with clean and violation-injected fixtures.
- Added `docs/security/skill-controller-review.md` containing the O04 security review checklist and threat model.

### Decisions
- The script uses `awk '/#\[cfg\(test\)\]/ {exit} {print}'` as a simple, effective approximation to ignore test code, documented directly in the guard script.
- For `guard_05`, rather than parsing complex Rust AST, the guard enforces that `src/context/skill_controller/` contains absolutely zero `async fn` outside of test blocks, guaranteeing that all caller entry points (like `audit_manifest_blocking`) must be synchronous and thus forcibly wrapped in `spawn_blocking` when called from async Axum handlers.

### Findings (Main Branch)
The following pre-existing violations were identified by the guard on `main`:
- `guard_03`: `src/context/skill_controller/audit/tests.rs` contains `.unwrap()` and `.expect()` calls outside a `mod tests` block (since the whole module is under `#[cfg(test)]` via its parent `mod.rs`).
- `guard_04`: `src/context/skill_controller/audit/tests.rs` contains `std::process::Command` calls.
