# OpenClaw Harness Optimizer (Self-Harness Steps 2 & 3)

This skill operationalizes the "Harness Proposal" and "Proposal Validation" stages of the Self-Harness paradigm. It uses the evidence bundle generated by the `openclaw-trace-analyzer` to propose diverse yet minimal candidate harness modifications, and then validates them using regression tests.

## 🛠 Core Responsibilities

1. **Harness Proposal:** Translate recurring failure patterns into candidate harness edits (e.g., changes to system prompts, tool schemas, or runtime policies).
2. **Parallel Generation:** Generate multiple, mutually distinct proposal bundles. Each edit must target a specific failure mechanism without replacing the overall control architecture.
3. **Proposal Validation:** Evaluate the candidate modifications through regression testing on held-in and held-out tasks.
4. **Promotion:** Accept a candidate edit only if it improves performance on the tasks without causing measurable degradation.

## ⚙️ Operating Procedures

### Step 1: Ingest Evidence Bundle
Receive the `Bt` (Evidence Bundle) from the `openclaw-trace-analyzer` skill. Analyze the failure clusters to understand the model-specific weaknesses.

### Step 2: Generate Proposals
Act as the "proposer" using the same base model. Generate `K` diverse candidate edits. 
- *Constraint:* Ensure edits are minimal. Do not rewrite the entire harness; only modify the surface needed to address the selected mechanism.

### Step 3: Regression Testing
Deploy each candidate harness (`h_t(j)`) temporarily.
- Run the agent on a held-in split (to check if the proposal fixes the targeted failure).
- Run the agent on a held-out split (to check for regressions).

### Step 4: Evaluate and Promote
Compare the pass rates against the baseline harness (`h_t`).
- *Rule:* A candidate is accepted ONLY if it improves at least one split without degrading the other.
- If accepted, merge the edit into the main branch/harness lineage in Xavier and promote it as the new baseline for that model.

## 🔧 Integration
- Interfaces with `xavier-self-harness-coordinator` to register new harness versions.
- Requires access to a localized test suite (Terminal-Bench or similar) for regression testing.
